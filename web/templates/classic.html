Local detection workbench

A workbench for detection rules.

Write a rule once and read it in eight SIEM languages. Test it against real log lines before it goes anywhere near production. Everything runs on this machine — nothing is uploaded, and there is nothing to install.

New to this? Take the example. It is a real credential-access rule, already filled in, and you can watch it change language as you switch the dialect at the top right.

lsass-dump-comsvcs local 
title: LSASS dump via comsvcs
level: high
logsource:
    product: windows
    category: process_creation
detection:
    selection:
        CommandLine|contains|all:
            - 'comsvcs.dll'
            - 'MiniDump'
    condition: selection
``` category=process_creation, product=windows --
    map this to an index and sourcetype before deploying ```
index=process_creation
| where (CommandLine LIKE "%comsvcs.dll%"
    AND CommandLine LIKE "%MiniDump%")
// title: LSASS dump via comsvcs
// severity: high
// author: SOC

process_creation
| where (CommandLine contains_cs "comsvcs.dll"
    and CommandLine contains_cs "MiniDump")
| project *
-- title: LSASS dump via comsvcs
-- severity: high
-- author: SOC
SELECT *
FROM process_creation
WHERE (CommandLine LIKE '%comsvcs.dll%'
    AND CommandLine LIKE '%MiniDump%')

It refuses rather than guesses

When a rule cannot be expressed in the language you asked for, you get a sentence explaining what would have gone wrong — not a best-effort translation that quietly matches more than you meant.

Three answers, not two

A test returns matched, no match, or could not tell. The third one matters: a rule testing a field your sample does not contain has not failed to match — the question was never answered.

Source table

Where the events come from — the index, table or data stream your SIEM reads. In Sentinel that is a table name like SecurityEvent; in Splunk it is an index.

An extra narrowing your SIEM applies before any event is read, written in that SIEM's own words. Leave it blank unless you are pasting a rule that had one. It is kept exactly as written and is never applied when you test against a sample here, because no sample can reproduce it — so a test says so rather than pretending.

Which field holds each event's timestamp. Only needed if the rule counts events over a time window; otherwise leave it blank.

What it matches

Steps run top to bottom: each one receives the events the step above it kept. Most rules are a single Filter.

Every rule ends in an output stage. That is not decoration: a pipeline with no stated output returns whatever the last stage happened to leave.
